An idempotency key makes a retry safe

The key belongs to the operation, not to each attempt.

Client
POST /charge · key abc-123
Server
charges the card, saves abc-123 → done
Client
response lost (timeout)
Server
client doesn't know if it worked
Client
retry · same key abc-123
Server
finds abc-123 already done
Client
same result, no new charge
Server
Charged once.
Check and save the key in one atomic step (unique index or row lock), or two attempts at once can both get through.
